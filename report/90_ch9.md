# 第九章　結論與建議

## 9.1　研究結論

本研究以 Olist 巴西電商資料為對象，從評論的情感分類一路延伸到負評的成因、預警與改善決策，四個研究問題的結論如下。

**RQ1：原論文的主要結果可以重現，但有兩處需要修正。** 在作者公開的相同切分下，BERTimbau 凍結與微調的 ROC-AUC 與原論文圖 1 的差距都在 0.2 個百分點以內（Large 微調 98.60%，論文 98.6%），模型排名也一致。然而，論文的 TF-IDF 基準偏低約 0.9 個百分點，使 BERT 的優勢被高估；論文表 3 與正文「微調在 Olist 上沒有幫助」的敘述與其圖 1 矛盾，本研究以 8 個種子與成對 bootstrap 檢定證明，微調在三種 BERT 上都顯著優於凍結向量（BERTimbau Large +0.44 個百分點）。錯誤分析顯示，一半的錯誤是星等與文字矛盾的標籤雜訊，模型已接近資料品質的上限。

**RQ2：資料量與成本會改變最佳選擇。** 訓練資料越少，預訓練模型的優勢越大；Qwen2.5-1.5B 以 LoRA 微調可達 98.70%，與 BERTimbau Large 相當，且只用 1,000 筆資料就有 98.08%，但推論成本是 BERTimbau Base 的 26 倍。零樣本與少樣本提示約 97%，且需要校正判斷門檻（可提高準確率 1–4 個百分點），但它們與領域無關，在跨領域情境中比轉移的 BERT 更穩健。

**RQ3：負評主要來自物流執行。** 延遲是最重要的因素；傾向分數配對、AIPW 與斷點迴歸一致顯示延遲使負評率增加約 45 個百分點，且顧客能容忍約 2 天的延遲，超過後負評率才急遽上升。多賣家分開出貨、賣家逾期交付與新賣家是其他主要風險；負評文字中約 53% 與物流有關。文字模型進一步發現，4–5 星評論中有 4.2% 其實在抱怨，延遲越久比例越高，只看星等會低估延遲的傷害。

**RQ4：預測可以轉為成本可控的行動。** 在預計送達日預警時，風險最高 1% 訂單的負評比例為 72%；依成本調整名單長度的政策，在成本不確定時有 73%–75% 的機率獲利且幾乎不會虧損，優於固定比例的名單。約 36% 的負評可藉由準時送達避免，RJ、BA、CE 等地區與多賣家訂單是優先改善的對象。

## 9.2　研究意涵

**學術意涵**：第一，本研究顯示獨立重現的價值：以多種子與統計檢定重新檢驗後，原論文的一項主要結論（微調在 Olist 沒有幫助）並不成立，且論文本身的圖表互相矛盾。第二，以星等作為情感標籤時，約有 3%–4% 的評論存在星等與文字的矛盾，這構成文字分類準確度的天花板，後續研究在比較模型時應考慮標籤雜訊。第三，結合文字模型與營運資料，可以發現單看星等或單看營運資料都看不到的現象（例如隱性不滿與延遲的關係）。

**實務意涵**：第一，導入情感分析時，不一定要使用最大的模型：BERTimbau Base 微調以極低的成本達到接近最佳的準確度。第二，電商平台改善顧客滿意度的首要工作是物流，而且應以「延遲不超過 2 天」為服務底線。第三，預警名單的長度應依成本動態調整，而非固定比例，並以 A/B 測試驗證實際的挽回效果。

## 9.3　研究限制

（1）**資料範圍**：只使用一個平台、2016–2018 年的資料；巴西的物流環境與其他市場不同，結論能否推廣需要更多資料驗證。

（2）**原論文的細節**：原論文沒有公開程式碼，TF-IDF 的前處理、表 3 的計算方式等只能依文字描述推測，差異的原因無法完全確認。

（3）**成本參數**：負評損失、聯繫成本與挽回率都是假設值；雖以敏感度分析與蒙地卡羅模擬檢驗，真實數值仍需由企業資料或實驗取得。

（4）**因果推論的假設**：傾向分數配對與 AIPW 只能控制可觀察的變數，若存在同時影響延遲與負評的未觀察因素，估計仍可能有偏誤；斷點迴歸只能說明斷點附近的效果。

（5）**大型語言模型的範圍**：受限於 11 GB 顯示卡記憶體，只測試到 3B 模型，且 3B 的 LoRA 超參數沒有另外調整、只跑 1 個種子；7B 以上的模型需要量化技術，本研究未納入。

（6）**錯誤歸類**：120 則錯誤樣本的歸類由 AI 助理初分、作者複核，只有一位複核者，未計算評分者間一致性。

## 9.4　未來研究方向

（1）**面向情感分析**：把一則評論中對「商品」與「物流」的情緒分開判斷，可以直接處理「商品很好但配送很慢」這類正負混雜的評論，也能讓改善建議更精準。

（2）**實地驗證**：以 A/B 測試驗證主動聯繫是否真的能挽回負評，並估計真實的挽回率與成本。

（3）**更大的語言模型與更好的提示**：以量化技術測試 7B 以上的模型，並調整 3B 模型的超參數，檢驗模型規模與準確度的關係。

（4）**持續監控與重新訓練**：把預警模型部署成每月自動重新訓練的流程，並監控預測表現隨時間的變化。
